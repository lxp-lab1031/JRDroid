# IQを保存してCodexへ添付する（v0.3.2-alpha）

ChatGPTへ直接共有した添付は、Codexへ切り替える際に保持されないことがあります。JRDroidから他アプリの入力画面を制御することはできないため、この版ではスマホのダウンロードへZIPとして保存する方法を追加しました。保存後のZIPは共有用の一時URIに依存しません。

## Galaxy S26での手順

1. JRDroidで受信し、「調査用 IQ を5秒取得」を押して取得完了を待ちます。
2. 新しい「IQ をダウンロードに保存（ZIP）」を押します。
3. 「保存しました：ダウンロード/JRDroid/…zip」の表示を待ちます。
4. ChatGPTを開き、**先にCodexへ切り替えてから**、添付の「＋」などからファイル選択を開きます。
5. 「ダウンロード」→「JRDroid」の `JRDroid-IQ-日時-識別子.zip` を選んで送ります。端末によっては「ファイル」「マイファイル」「参照」などから選びます。

保存名の日時はZIPを保存したスマホの時刻です。取得時の周波数・取得開始時刻等はZIP内のメタデータに記録されています。保存を繰り返しても名前を変えて残し、以前のZIPを上書きしません。共有リンクを開いてからCodexへ切り替える操作は、この方法では不要です。

保存前に他アプリへ移動する場合も、完了表示を待ってください。保存完了後のファイルはJRDroidの画面を離れたり、一時IQが次の取得で置き換わったりしても残ります。ダウンロードに保存したZIPはアプリから自動削除しません。不要なものは「マイファイル」等で削除できます。

## ファイルの内容

ZIPは `capture.jrd-iq` を1ファイル含みます。元のJSONヘッダーとunsigned 8-bit IQのバイト列は変更せず、音声WAVや復号済みデータへ変換する機能ではありません。途中で停止したIQは元の `complete:false` と実際の取得量を保持します。ZIP自体を添付できれば、解凍してから添付し直す必要はありません。

従来の「保存した IQ を共有」はそのまま利用できます。これは一時コピーの共有で、ダウンロードへの保存とは別の操作です。

## Android側の保存方式

- Android 10以降（API29+）はMediaStoreを利用し、共有ストレージの `Download/JRDroid` に直接保存します。ストレージの全体アクセス権限や旧式の書き込み権限は要求しません。
- Android 9（API28）はシステムの保存先選択画面を開きます。「ダウンロード」等を選んで保存してください。保存先はユーザーが選択した場所です。
- ファイルの圧縮・書き込みは受信処理やUIとは別のワーカーで実施します。ワーカーはActivityを保持せず、アプリの画面を離れても処理を継続できます。ただし保存中のプロセス終了時には再保存が必要です。
- MediaStoreでは書き込み中を未公開にし、ZIPを閉じてから公開します。保存失敗時は未完成の出力の削除を試み、画面に失敗を表示します。削除自体が保存先から拒否された場合の例外も診断へ残します。
- 保存対象は従来の5秒相当IQとヘッダーに制限します。アプリの受信・同期・音声出力・選局・ゲイン・ppmはこの変更で変えていません。京急の実電波による音声復号は引き続き未確認です。

## 開発環境での読み取り

```bash
python3 scripts/inspect-capture.py /path/to/JRDroid-IQ-example.zip
# 従来の生ファイルも利用可能
python3 scripts/inspect-capture.py /path/to/capture.jrd-iq
```

このスクリプトはメタデータと長さの確認用で、音声の復号成功を示すものではありません。

## 確認状況

完全取得・途中取得のメタデータと全IQバイトの一致、元の一時取得と独立して保存できること、出力開始・書き込み・クローズ・公開時の失敗処理をホスト試験で確認しました。実行結果は [検証記録](VALIDATION.ja.md) に記載しています。

Android実機のMediaStore・保存先選択画面と、ChatGPTアプリのCodexでファイルを選んで添付する一連の操作は未確認です。Galaxyでの実機確認が必要です。
