# 京浜急行対応の調査状況

状態: **v0.3.1-alphaで146 MHz帯の基地局16設定へ置き換えました。京急等の音声復号は未確認です。** 旧142 MHz帯が移動局側とのユーザーの訂正と、新たな基地局設定写真に基づく変更です。周波数の選局設定を修正したもので、私鉄の専用フレーム・コーデックを実装済みとしていません。

## 現在の実装

JR Dタイプ22波と、写真の146 MHz帯基地局16波のみ選局できます。旧142 MHz帯の移動局16波はJava・RTL-TCP・Rust受信入口で拒否し、保存された旧設定だけ対応する基地局側へ移行します。基地局写真にはK1/K2/K3/北総のデータ4波・音声12波があり、[設定一覧](PRIVATE_BASE_STATION_TEST.ja.md)に記録しました。K1/K2/K3の会社・運用区間ごとの割当を独立に確認した一覧ではありません。

受信は1波ずつで240 kS/s、40.2 dB、0 ppmを使います。写真の146.470000 MHzは広帯域窓の中心で、選局する波とは区別しています。Windows写真の1.024 MSPS・38.6 dBへ変更したものではありません。

復調は既存JR用のπ/4-DQPSK、フレーム同期は384 bit / 40 ms、音声は158 bitのModified RL-CELPペイロードから合成します。146 MHz値も上流のSlotted形式へ渡しており、私鉄の実信号との互換性は未確認です。USBドライバー連携・IQ保存・停止・PCM再生・ミックス出力は既存処理を継続しています。

JRのD4音声第1波・旅客一斉、TikTokミックス、Bluetooth、バッテリー消費低減についてユーザーの実機報告があります。京急等の確認報告としては扱いません。

## 三菱電機技報の一次資料で確認した仕様（2026-11-04）

ユーザーから提供されたPDF「大手私鉄向け150MHz帯空間波デジタル列車無線システム」（杉浦哲広・延澤大・手嶋牧子、三菱電機技報 Vol.90 No.6、2016、27–31〔347–351〕頁）を全文確認しました。2015年に京浜急行電鉄の全線87 kmへ納入したシステムを説明するメーカー資料です。

出典: https://www.giho.mitsubishielectric.co.jp/giho/pdf/2016/1606107.pdf

Web接続からは本文を取得できませんでしたが、添付されたPDFを解析・閲覧できました。対象ファイルのSHA-256は `f51466abcd2d11064affda6f4e6cc104fec66a4f72482bb2fcf70938c6b3e7e4` です。PDF本体と本文全文はリポジトリへ転載していません。

**PDFの3ページ目、誌面29〔349〕頁の節3.1で、音声コーデック名はRL-CELPと確認できました。** 左段末尾から右段へ続く文章に「列車無線専用音声コーデック（Rail system－Code Excited Linear Prediction：RL－CELP）」と明記されています。これまでの「京急のコーデック名は未特定」という調査結果を、この資料が説明するシステムについて更新します。

| 項目 | 資料に記載された内容 | 根拠 |
|---|---|---|
| 音声コーデック | RL-CELP | PDF p.3／節3.1 |
| アクセス方式 | FDMA／SCPC | PDF p.2／表2 |
| 周波数帯・波数 | 150 MHz帯4対波 | PDF p.2／表2 |
| 周波数間隔 | 6.25 kHz | PDF p.2／表2 |
| 変調方式 | π/4シフトQPSK | PDF p.2／表2 |
| 無線区間の伝送速度 | 9.6 kbit/s。QPSKの2 bit/symbolから4,800 symbols/sと計算できる | PDF p.2／表2、シンボルレートは計算値 |
| 同一波干渉対策 | 送信時間ダイバーシチ・適応等化受信 | PDF p.3／節3.1・図2 |
| 区域ごとの回線構成 | 無線通信制御1、通話2、運行情報等のデータ通信1 | PDF p.3／節2.4 |

ただし、**本文には「改良型／Modified」の表記、音声ペイロードのビットレート、音声フレーム長、同期語、誤り訂正・インターリーブ・スクランブルの詳細は記載されていません。** 9.6 kbit/sは無線伝送速度で、音声コーデックのビットレートとは区別します。JRDroidが使う改良型RL-CELPの158 bit / 40 ms（3.95 kbit/s）を、この資料から京急の仕様として確定することはできません。

変調方式と伝送速度は既存JR用DSPを試す根拠になりますが、同じRL-CELPの呼称だけでビット列の互換性を保証できません。現在の384 bit／40 msフレーム・同期語・チャネル復号・音声パラメータの適合は、146 MHz帯基地局の実信号で確認する必要があります。既存DSPには等化処理がありますが、本文の送信時間ダイバーシチの遅延条件に適合するかは未確認です。

資料の「通話2回線」と、Windows写真の「データ1・音声3」の表示から、各プリセットの実際の用途を直接対応づけることはできません。写真に従った表示・周波数は維持し、特定の波を推測で別用途に変更しません。また、この資料の対象は京急の2015年納入システムであり、京成・北総の仕様や現在の全運用へ無条件に適用しません。

## 公開JR実装の確認

https://github.com/soltia48/jr-conventional-line-radio-receiver のコミット `994587059432fbb4df1e370dd2fc62a4becc0aa1` のREADME・docs・音声説明を確認しました。対象はJR在来線で、確認した文書に京急の方式を裏付ける説明はありませんでした。音声説明は改良型RL-CELP・158 bit / 40 ms（3.95 kbit/sのペイロード）・出力8 kHz PCMです。京急の仕様の根拠としては使いません。現在同梱している上流コードとモデルは変更していません。

JR向けの派生C実装 https://github.com/tallcat4/mrl-celp-c も見つかりましたが、京急の採用方式についての独立した資料ではありません。今回アプリには導入していません。
