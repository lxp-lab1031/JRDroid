# 最初の実装方針

## 境界

将来のデータ経路は`USB → RTL-SDR制御 → IQ → 復調・フレーム解析 → 音声復号 → AudioTrack`。
現時点で実装済みなのはUSB機器の列挙とReceiverConfigだけです。
この経路は設計案であり、通信方式やライブラリが確定したという意味ではありません。

- `MainActivity`: 表示とユーザー操作。DSPやUSBストリーミングを置かない。
- `receiver/`: 周波数などの設定。Hz単位の整数を保持。未確定のサンプルレートは初期値を仮定しない。
- `usb/`: 次段階で追加。USB許可、切断、ドライバーへの接続を担当。
- `dsp/`, `audio/`: 復調方式とコーデックが決まった段階で追加。

空の実装や成功を返すダミー受信は用意しません。

## 実装順序・完了条件

1. **起動・列挙（今回の範囲）**
   - SDK環境でassembleDebugとlintDebugを実行する。
   - S26のOS/APIレベルと型番を記録し、USB未接続・接続・抜去後の再確認を試す。
   - 352.6250 MHz表示、未実装表示、USB機器のVID/PIDが確認できること。
2. **USB許可とRTL-SDR制御**
   - 実物のチューナー型式とUSB ID、USB-Cホスト対応アダプター、給電条件を確認。
   - Java USB直接制御またはネイティブドライバーを比較し、保守状況・ライセンス・arm64対応から選定。
   - AndroidのUSB許可フローを実装。許可拒否・抜去・再接続時も安全に停止できること。
   - USB記述子が見えるだけで「RTL-SDR対応」「受信成功」と判定しない。
3. **IQ取り込み**
   - 352,625,000 Hzへ設定できるチューナーであることを確認。
   - サンプルレート、ゲイン、PPM補正、IQ形式を実機・既存受信環境から確定。
   - ワーカースレッドと上限付きバッファを使用。停止時のUSB解放、欠落・過負荷を可視化。
4. **復調・復号**
   - Windowsで使用したソフト名・版、設定、利用可能な仕様を確認する。
   - WAVが音声かIQかを確認。音声WAVだけではIQ復調の検証入力にならない。
   - 適切な検証データでフレーム検出と音声復号を別々に確認する。
   - 外部ライブラリの再配布条件を確認し、必要に応じてNOTICEを追加。
5. **音声再生**
   - PCMのサンプルレート・チャンネル数を確定後AudioTrackへ接続。
   - 停止、再開、USB切断時の無音化・リソース解放を確認。

## 当面含めないもの

バックグラウンド受信、録音、ネット配信、自動チャンネル走査、サーバー、NDK、DIフレームワーク。
必要が具体化してから追加します。受信開始ボタンも実処理ができるまで設けません。
