# 停止時クラッシュへの対応（v0.2.2-alpha）

2026-11-03、ユーザーから「周波数を変えるために停止するとアプリが落ち、スマホが『たびたび停止しています』と警告する」との報告を受けました。警告対象は RTL-SDR driver ではなく JRDroid 本体と確認しました。実機の例外スタック・ANR・ネイティブクラッシュ記録はまだ入手しておらず、原因を一意に確定したとはしていません。

## コードで確認した問題と修正

- 停止ボタンの呼び出し先で、AudioTrack の pause と TCP への終了コマンド・close を直接行っていました。これらの待ちがUIスレッドへ波及しないよう、停止ボタンはキャンセル通知だけにしました。通信の終了は専用スレッドへ移しました。
- AudioTrack を音声スレッドで書き込みながら、UI/DSPスレッドで pause・flush・release していました。音声スレッドが2秒以内に終了しなくても解放する処理もありました。音声出力は1本の音声スレッドで作成・使用・解放する形に統一し、終了完了を受信ワーカーで待ちます。UIスレッドでは待ちません。
- `WRITE_BLOCKING` を止めるための別スレッドからの pause を廃止しました。`WRITE_NON_BLOCKING` と、満杯時だけの割り込み可能な20 ms待機を使います。無音時はキュー待ちと出力休止を継続します。
- UIと受信ワーカーの両方からドライバー終了コマンドを送っていた処理を、受信セッションごとの一度だけの終了に統一しました。
- キャンセル・音声キュー・接続を受信ごとに分離し、終了が済むまで次の受信を許可しません。旧セッションの音声フォーカス通知が新しい受信を止めないよう、セッションの一致も確認します。
- 後片付け中の例外を記録し、音声フォーカス・wake lock・通知の残りの後片付けを継続します。

## 確認したこと

- Rust93 passed / 0 failed / 1 ignored、JVM/JNI18項目成功。
- ネットワークへの書き込みを意図的に止めても、停止要求の呼び出し元が待たされないことを確認。
- ドライバー終了が一度だけ送信されること、接続前のキャンセルと終了時の例外が処理されることを確認。
- ドライバーへの初期設定中に停止しても、周波数設定と終了コマンドのbyte列が混ざらないことを確認。
- 無音待ち・再生中・出力満杯で200回の停止・再開を実施し、音声出力への全操作と解放が所有スレッドで行われることを確認。
- 解放処理を遅らせた模擬出力で、終了待ちが先に完了せず、別スレッドから出力を強制解放しないことを確認。
- 通常版・別インストール版のAPKビルド・lint・署名・16 KiB整列を確認。旧版と同じアプリID・署名、versionCode4で更新できます。

これらはホスト上の回帰試験です。Galaxy S26・AndroidのAudioTrack・USB SDRでの停止クラッシュの再現と解消は、まだ確認できていません。RustのDSP・音声復号処理は今回変更していません。

## 更新後の操作と診断

1. 今のアプリと同じ種類（通常版 / 別インストール版）のv0.2.2-alphaで更新します。データを消す必要はありません。
2. 旅客一斉で受信し、「停止」→「停止中」になることを確認します。
3. 別のDチャンネルを選び「受信開始」します。無音時と音声再生中の両方で、停止・選局・再開を何回か確認します。
4. まだ異常がある場合は、再起動後に画面下の「停止・クラッシュの診断情報」を開き、「コピー」で診断内容を取得できます。

Android 11以降では、このアプリの終了理由（ANR / Java / native等）と、OSが保持していれば直近のクラッシュのtraceを表示します。アプリ側で記録できた例外も表示します。読み取りは別スレッドで行い、情報は端末内だけに保存します。自動送信は行いません。旧版でのクラッシュ記録がOSに残っていれば、更新前の原因も確認できる場合があります。

スマホのディープスリープ設定は停止処理の不具合を修正するものではなく、画面消灯中の受信へ影響する可能性があります。まず修正版で停止動作を確認してください。
