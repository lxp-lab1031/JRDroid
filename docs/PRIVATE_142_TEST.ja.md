# 142 MHz帯の試験受信・IQ取得（v0.3.0-alpha）

**京急・京成・北総の音声復号は未確認です。** この版は、ユーザー提供のJR-D Receiver設定画像の周波数を選び、既存JR用の復号処理との互換性を試すための調査版です。専用の私鉄フレーム形式・音声コーデックを実装済みとしていません。

画像には142.47 MHz中心・1.024 MSPS等の表示がありますが、同時に `No device found` と音声・データの0件表示があり、実受信成功の証拠とは扱いません。K1/K2/K3を各会社に割り当てる対応表も、この画像だけから決めていません。

## 試す手順

1. 現在のアプリと同じ種類（通常版 / 別インストール版）のv0.3.0-alphaへ更新します。
2. 受信を停止し、「受信対象・周波数を選択」→「142 MHz帯 · 私鉄設定の試験受信」を選びます。
3. 実際に受信する設定を選びます。画像で「音声」と表示された項目にはK1-1等があります。K1/K2/K3と会社の対応は未確認です。
4. 142 MHz帯を受けられるアンテナを用意し、「受信開始」を押します。JR設定へは同じ受信対象メニューから戻れます。
5. IQ数、同期フレーム、有効音声、PCM、実際の音声を確認します。IQや同期だけが増えても音声復号成功とはしません。

142 MHz設定では「前の設定」「次の設定」は画像の一覧順です。隣接する周波数差は一定ではありません。JRモードの±6.25 kHz操作は従来どおりです。登録されていない142 MHz値は直接入力でも拒否します。

受信レートは従来の240 kS/s、ゲイン40.2 dB、補正0 ppmを使い、選択した1波の中心に合わせます。Windows画像と同じ広帯域同時受信ではありません。内部ではJR互換のπ/4-DQPSK/40 msフレーム/Modified RL-CELPを試し、142 MHz値は上流のSlotted形式へ渡します。この仮定が実際の私鉄信号に適合するかは未確認です。

## 同期しない・音声が出ない場合のIQ取得

1. 受信中に「調査用 IQ を5秒取得」を押します。
2. 保存完了表示まで待ちます。取得は5秒相当（1,200,000複素サンプル、2,400,000 byte）で終了します。
3. 「保存した IQ を共有」で送信先を選びます。端末内の共有機能で選択したアプリにだけ読み取り権限を渡します。自動送信はしません。
4. 解析を依頼する際は `.jrd-iq` ファイルを添付し、受信した設定、放送があったか、画面の同期・音声・PCM数も添えます。必要ならファイルをZIPにして添付できます。

データは未復調のunsigned 8-bit interleaved I/Qです。最初の行がUTF-8 JSONメタデータ、改行以降がraw IQです。周波数、要求レート・ゲイン・ppm、端末での取得開始時刻、実際のbyte数、取得完了フラグを含みます。設定値を機器から読み戻したものではありません。5秒相当のデータが揃ってもドライバー側の欠落ゼロを保証しません。

停止前に5秒分が揃わなかった場合は `complete:false` と実際のbyte数を保存し、画面にも途中取得と表示します。開始前に停止した場合は中止扱いです。ファイル出力は専用ワーカーで行い、保存失敗を理由に受信を停止させません。メモリ上の取得サイズと保存待ちキューに上限を設けています。

最新の取得ファイルはアプリの非公開キャッシュに保持します。共有時には別の不変コピーを作り、前の共有URIで将来の取得データが読まれないようにしています。共有コピーは最大4件の一時キャッシュです。キャッシュ削除や古いコピーの整理で共有URIが利用できなくなる場合があります。必要なデータは共有先で保存してください。取得ファイルは `.gitignore` に指定し、GitHubへのソース公開物には含めません。

ホストではメタデータと長さを次のように確認できます。

```bash
python3 scripts/inspect-capture.py /path/to/capture.jrd-iq
```

このスクリプトはファイル形式の確認で、私鉄の音声を復号するものではありません。

## 現時点の確認

- JR22波を維持し、画像由来16設定をJava・RTL-TCP・JNI・Rustへ渡せることを試験しました。
- 142 MHzの設定でJR形式の合成IQを入力しPCMが出ることを確認しました。これは京急の実電波との互換性を示しません。
- 取得上限、byte列の保持、途中取得の区別、共有コピーの不変性、パス制限、一時共有ファイル数の上限をホストで検証しました。
- Android実機での142 MHz受信・専用方式の復号・IQ保存と共有は未確認です。実機データで次の調査が必要です。
