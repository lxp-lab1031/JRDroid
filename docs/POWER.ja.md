# 省電力処理（v0.2.1-alpha）

追加の実機報告として、ユーザーからバッテリー消費の低減を確認したとの回答を受けました。比較した版・受信時間・電池残量・放送量などの測定条件は未記録のため、定量的な改善率は未測定のままです。以下のCPU・Java割当の表は従来どおりホスト試験の記録であり、この実機報告の数値化ではありません。

**v0.2.2-alphaでの変更:** 停止時クラッシュの報告を受け、AudioTrackを1本の音声スレッドで管理するよう変更しました。音声書き込みは非ブロッキングへ戻し、満杯のときだけ20 ms待機します。無音時の休止・IQバッファー再利用・診断削減は維持しています。以下の比較数値はv0.2.1-alphaの記録であり、v0.2.2-alphaの電池消費測定ではありません。[停止処理の修正](STOP_FIX.ja.md) を参照してください。

音声受信と画面消灯中の継続動作を維持するため、受信そのものを間引かず、不要な待機・診断・メモリ確保を減らしました。周波数選択は v0.2.0-alpha と同じ22波です。

## 変更

- 音声 PCM が届いてから AudioTrack を再生開始します。音声が来ない間のスピーカー出力を休止します。
- 音声キューが空になって1秒経過し、書き込んだ全サンプルの再生が終わったことを確認してから休止します。まだ再生されていない末尾を flush で消さないようにします。次の PCM で再生を再開します。
- 専用の音声スレッドで `WRITE_BLOCKING` を使い、従来の5 msごとの書き込み再試行をなくしました。停止時は pause・ソケット終了・スレッド割り込みで待機を解除します。
- 音声がない待機中はキューの `take()` で待ち、従来の200 msごとの空キュー確認をなくしました。
- TCP の断片を32,768 byteの IQ ブロックにまとめます。240 kS/sでは約68 ms分です。小さな断片ごとのJNI呼び出しを減らす一方、入力待ちの遅延が最大約68 ms分増える場合があります。
- Rust の入力 byte / IQ バッファーを再利用し、符号付きbyteから符号なしbyteへの追加のコピーを削減しました。無音時の空 PCM 配列も再利用します。
- 表示中のステータス取得と画面更新は約1秒ごとです。画面非表示中は軽量ステータスを約5秒ごとに取得し、コンスタレーション・EVM・履歴コピーを省きます。画面復帰時には次の IQ ブロックで更新を要求します。

サンプルレート240 kS/s、ゲイン40.2 dB、補正0 ppm、二経路のDSP・フレーム検査・音声合成は従来のままです。弱い信号の処理を省くモードにはしていません。画面消灯中もCPUの受信処理が継続できるよう、受信中の時間制限付き wake lock は継続使用します。

## ホストでの確認

- Rust 93 passed / 0 failed / 1 ignored。JVM/JNI 13項目成功。
- 小さい IQ チャンクと32,768 byteのバッチから、同じ合成信号に対して同一の PCM 列を得ることを確認しました。
- 断片化・奇数長・EOF直前の部分ブロックで、IQ byteを欠落させず保持することを確認しました。
- 部分書き込み、再生末尾が残っている間の休止禁止、全再生後の休止、次の音声での再開を模擬出力で確認しました。
- 空 PCM 配列の再利用と、非表示時にEVMを計算済みの値として返さないことを JNI 経由で確認しました。

### CPU・Java割当の比較

同じ Linux x86_64 / OpenJDK21 で、v0.2.0-alpha のホストJNIライブラリと変更後を比較しました。受信時間9秒相当（4,320,000 byte）の入力を、実時間の待機なしで処理しています。各条件で1回ウォームアップ後に3回測定した中央値です。CPU時間は処理スレッドの `ThreadMXBean` 値、Java割当は同スレッドの値です。実際のAndroidの電池消費・USB電力・AudioTrack・無線環境は測っていません。

| 入力・版 | CPU時間 (ms / IQ 9秒相当) | Java割当 (byte) | PCM出力サンプル |
|---|---:|---:|---:|
| 無信号・v0.2.0 | 948.633 | 11,616 | 0 |
| 無信号・v0.2.1表示中相当 | 813.248 | 3,200 | 0 |
| 無信号・v0.2.1非表示相当 | 844.273 | 384 | 0 |
| 合成音声・v0.2.0 | 2,321.958 | 150,432 | 69,440 |
| 合成音声・v0.2.1表示中相当 | 2,145.867 | 143,192 | 69,440 |
| 合成音声・v0.2.1非表示相当 | 2,092.633 | 140,376 | 69,440 |

この試験で CPU 時間とJava割当は減りましたが、**スマホの電池持ち改善率を表す数値ではありません**。Rust内部全体やOSの全メモリ割当をJava割当値に含めてもいません。

`scripts/check.sh` 実行後、任意の追加比較として次を利用できます（CPUを使うベンチマークなので、通常の受信時には実行不要です）。

```bash
java -Djava.library.path=native/target/release -cp app/build/host-tests \
  jp.jrdroid.PowerBenchmark app/build/host-tests/synthetic.u8 visible
java -Djava.library.path=native/target/release -cp app/build/host-tests \
  jp.jrdroid.PowerBenchmark app/build/host-tests/synthetic.u8 hidden
```

## 実機で必要な確認

v0.2.1-alphaの画面消灯中の受信、最初の発話と末尾、無音からの再開、停止・再開、遅延、発熱、電池消費は実機確認が必要です。旧版についての実機成功報告を、この版の成功としては扱っていません。

電池消費を比較する場合は、旧版と新版で同じアンテナ・周波数・ゲイン・USB接続・音量・画面状態にし、それぞれ30分程度の受信前後の電池残量を記録してください。音声放送の量が違うと処理量も変わるため、その条件も記録します。

SDR ドングルへのUSB給電はこの変更では減りません。給電対応のOTGハブを使うことも選択肢ですが、端末・ハブの組み合わせでUSBホストと給電が両立するかの確認が必要です。受信を終えたら停止し、不要なドングルを外すことも電池消費を減らします。
