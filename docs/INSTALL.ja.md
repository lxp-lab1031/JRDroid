# APK の導入・実機評価

この α 版はクラウドでビルドと合成信号の復号を確認し、2026-10-28 にユーザーから Galaxy S26 のスピーカーで実際の放送音声が聞こえ、画面消灯中も音声が継続しているとの報告を受けました。長時間の安定性や音声品質の比較、通信オフ・長時間の省電力状態での動作は引き続き評価が必要です。確認済みの範囲は [検証記録](VALIDATION.ja.md) に記載しています。

v0.2.1-alpha は [省電力処理](POWER.ja.md) を追加した版です。同じ種類の旧版へ上書き更新する構成です。更新後は最初の発話・末尾・無音からの再開・画面消灯中の音声・停止操作を実機で確認してください。省電力処理の電池消費改善率は未測定です。

## 用意するもの

- Galaxy S26（arm64-v8a）。Android 16 を主な想定としています。
- RTL2832U＋R820T の SDR ドングル、USB Type-C OTG アダプター、352 MHz 帯用のアンテナ。
- 必要に応じて給電できる USB ハブ。ドングルが切断を繰り返す場合は給電も確認します。
- [RTL-SDR driver](https://play.google.com/store/apps/details?id=marto.rtl_tcp_andro)（Android パッケージ `marto.rtl_tcp_andro`）。JRDroid の APK には含めていません。初回導入には通信が必要です。

別のドライバーや独自名でビルドしたドライバーには自動接続しません。今回の受信形式は R820T/R828D を持つ RTL2832U 向けで、HackRF・SDRplay の入力形式には対応しません。

## インストール

1. `app/build/outputs/apk/debug/app-debug.apk` を端末にコピーします。
2. ファイル管理アプリから APK を開き、そのアプリに必要な「不明なアプリのインストール」許可を与えてインストールします。Samsung の設定で APK 導入が制限されている場合は、その端末の設定を確認してください。
3. JRDroid を開きます。通知許可を求められたら、受信中の通知と停止操作のため許可してください。

開発用 PC がある場合は、USB デバッグを許可し `adb install -r app/build/outputs/apk/debug/app-debug.apk` でも導入できます。**PC はこの導入手段の一つで、受信時には不要です。** デバッグ署名の APK なので、公開ストア版としての署名・配布・アップデート互換性は準備していません。

## 旧版の更新が進まない場合

旧版との更新処理を避けるため、アプリ ID を `jp.jrdroid.standalone` に分けた「JRDroid 別インストール」版もビルドできます。元の JRDroid を削除せずに新規インストールする用途です。受信処理は通常版と同じで、旧版の設定・データを移行するものではありません。

```bash
./gradlew --no-daemon assembleStandalone lintStandalone
```

成果物は `app/build/outputs/apk/standalone/app-standalone.apk` です。既存版との署名・バージョン競合を避けるための別パッケージであり、インストーラーが応答しない、保存容量が足りない、端末側で APK 導入が制限されている等の原因を解消するものではありません。別インストール版でも失敗する場合は、画面のメッセージを確認してください。2つの JRDroid で同時に受信を開始しないでください。

## 受信

1. アンテナと SDR ドングルを接続して、OTG で Galaxy に挿します。
2. 停止中に「周波数・D チャンネルを選択」、MHz の直接入力、または ±6.25 kHz ボタンで周波数を設定します。初期値は旅客一斉の352.62500 MHz、選択は次回起動時にも保存されます。[周波数一覧](D_CHANNELS.ja.md) を参照してください。
3. JRDroid の「受信開始」を押します。RTL-SDR driver に切り替わったら、対象の USB 機器へのアクセスを許可します。
4. JRDroid に戻ると、端末内の `127.0.0.1:12345` に接続します。アプリは選択した周波数・レート・ゲインを設定し、初期 IQ を捨ててから復調します。
5. 「IQ 受信中」→「フレーム同期中」となり、放送中に有効音声・PCM 数が増えるか見ます。音声数は累計で、現在の発話中状態を示すものではありません。
6. Galaxy のメディア音量を上げます。アプリは内蔵スピーカーを優先するよう要求しますが、Bluetooth・有線機器などを含む最終的な音声経路は Android が管理します。
7. 「停止」または受信通知の「停止」で終了します。周波数の変更は停止処理完了後に行ってください。ドライバーにも終了コマンドを送ります。

音声フォーカスが失われた場合は停止し、再開には「受信開始」が必要です。受信中は foreground service と時間制限付き wake lock を使う設計で、画面消灯中の継続再生はユーザーの実機試験で確認されました。長時間の消灯・Samsung の省電力制御・電話の割り込みでの動作は追加確認が必要です。Android がプロセスを終了した場合、受信を自動で再開する設計にはしていません。

v0.2.0-alpha では 352.53750〜352.66875 MHz を6.25 kHz刻みで選局できます。初期値は352.62500 MHzです。240 kS/s、ゲイン40.2 dB、補正0 ppmは固定で、ゲインや補正の編集は未実装です。受信中・ドライバー起動中は選局を無効にします。初めに旅客一斉で従来の受信を確認し、停止→別チャンネル選択→受信再開で画面と通知の周波数・実際の受信を確認してください。

## 状態とエラーの読み方

| 表示・状況 | 次に確認すること |
|---|---|
| ドライバーがない | 上記パッケージの RTL-SDR driver を導入する |
| USB 機器が0台 | OTG 対応、ケーブル、給電、端末の USB ホスト認識を確認する |
| ドライバー開始失敗 | ドライバーの USB 許可を確認し、ほかの SDR アプリを停止する。JRDroid の USB 数は全 USB 機器の列挙数で、RTL2832U の認識成功を示さない |
| 端末内ドライバーへ接続できない | ドライバー終了後に再度開始する。ポート12345を使う別プロセスがないか確認する |
| ヘッダー不正・想定外チューナー | 対象ドライバーと R820T/R828D の組み合わせを確認する |
| IQ は増えるがフレーム同期待ち | アンテナ、放送の有無、受信レベル、周波数補正を検討する。Windows で成功していた同じ条件と比較する |
| 同期するが有効音声が0 | データのみの区間や放送のない時間は0のまま。音声放送中の CRC/FEC 受理を確認する |
| PCM は増えるが無音・不明瞭 | メディア音量、音声出力先、通話中でないか、上流モデルの音声品質を確認する |
| 5秒間応答がない | USB 給電、ドングルの抜け、ドライバー側の停止を確認する |
| 音声処理が追いつかない | キューに2秒を超える PCM が溜まると、遅延を蓄積し続けずエラー停止する。端末負荷・発熱を記録する |

EVM は上流 DSP の未校正の調整指標で、SNR・BER・聞き取り品質の保証ではありません。RTL-TCP の機器設定には応答確認がなく、USB 側の欠落を通知する仕組みもありません。

## 実機で必要な受け入れ試験

以下を確認できるまでは「動作する音声受信版が完成」としません。

- 対象 Galaxy S26 と RTL2832U/R820T の型番、Android・ドライバーのバージョンを記録する。
- USB 許可後に対象チューナーとして接続し、実際の352.6250 MHzで同期・有効音声・PCM数が増える。
- Windows で確認済みの放送と比較し、スマホのスピーカーで実際の発話を聞き取れる。
- Wi-Fi・モバイルデータをオフにした状態で、同じ受信経路が動く。
- 10分以上の連続受信で、音切れ・遅延増加・過度の発熱がないか記録する。
- 停止→再開、USB 抜去、USB 許可拒否、他アプリによる音声割り込み、画面消灯、通知からの停止を確認する。
- 音声がない区間・弱電界・データのみの区間で、同期や音声成功を誤表示しないことを確認する。

問題の報告には、画面のエラー全文、同期・音声・PCM 数、端末/OS/ドライバー情報、発生した操作を添えると切り分けに役立ちます。
